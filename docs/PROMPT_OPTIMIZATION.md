# 简历解析 Prompt 评测驱动优化记录

> 记录通过「评测 → 分析 → 优化 → 复测」闭环迭代 LLM 简历解析效果的两轮过程。
> 评测套件：`evaluation/`（10 份标准简历 + 6 份高难度仿真简历，含标准答案）
> 相关报告：`evaluation/report_parse.md`、`evaluation/report_matching.md`

---

## 一、评测集设计

| 集合 | 数量 | 特征 |
|---|---|---|
| 标准集 | 10 | ATS 理想版式、字段规范、技能用字典标准名 |
| 困难集 | 6 | 故意埋坑：隐含年限（只给起止时间）、无技能栏（技能埋描述）、版式乱序、技能别名（Python3/Vue.js）、段落式口语化、字段矛盾（本科vs硕士）、错别字、应届无经历 |

**设计动机**：首轮全标准集跑出 100% 属"自己出题自己答"的同源偏差，
加入困难集后指标回落到真实区间，掉分点即优化方向。

---

## 二、第一轮（基线）：2026-08-30

| 指标 | 数值 |
|---|---|
| 解析综合字段准确率 | **95.8%**（标准≈100% + 困难≈85% 加权） |
| 技能通过率（召回≥0.8） | 12/16 |
| 匹配 M1 命中率 | 90.6% |
| 匹配 M2 技能重合度 | 74.2% |

### 掉分点分析（三类）

| 问题 | 涉及样本 | 根因 |
|---|---|---|
| **技能泛化**：简历写 MySQL 被抽成 "SQL" | 6 份 | LLM 倾向抽象化（SQL 是 MySQL 上位词） |
| **隐含年限只算最近一段** | 何骏（4年→算成2年） | 只取最近经历段，未累加总跨度 |
| **别名+埋描述组合漏抽** | 高逸辰/邓诗涵（召回 0.5） | Vue.js/MySQL 写在句子里被跳过 |

### 匹配侧问题

王芳（前端）命中率 0%：解析抽出的技能窄（仅 Vue 命中），导致推荐全歪——
**数据侧链条：解析技能不全 → 简历向量偏窄 → 召回岗位不匹配**。

---

## 三、第一轮优化动作：Prompt 加规则

`llm_module/models/prompts.py` 的 `RESUME_PARSE_PROMPT` 新增两条文字规则：

1. **work_years 规则**：未直接写年限时按「所有工作经历起止时间的总跨度」推算
2. **skills 反泛化规则**：保留具体技术名（MySQL ≠ SQL、Spring Boot ≠ Java），
   且技能可从工作/项目描述中提取，不只看技能栏

---

## 四、第二轮：2026-08-30

| 指标 | 第一轮 | 第二轮 | 变化 |
|---|---|---|---|
| **匹配 M1 命中率** | 90.6% | **100%** | ✅ +9.4%（王芳 0%→全过） |
| **匹配 M2 重合度** | 74.2% | **83.3%** | ✅ +9.1% |
| 解析综合准确率 | 95.8% | 95.1% | -0.7% |
| work_years | 93.8% | 87.5% | ❌ 修一个坏一个 |
| 技能通过率 | 12/16 | 12/16 | 泛化未修复 |

### 结论

- ✅ **"从描述提取技能"规则显著生效**：解析技能变全 → 简历向量变准 →
  匹配指标大涨。这是本轮最大收益，验证了「解析质量直接决定推荐质量」的链路。
- ❌ **文字规则的局限**：模型对长 prompt 里的文字规则遵循度低
  （泛化未修）；年限规则执行不稳（沈书瑶从对变错——模型尝试按规则计算反而算岔）。

---

## 五、第三轮优化：Few-shot 示例替代文字规则

**原理**：LLM 对示例的模仿能力远强于对规则的服从。把两条规则改写为对照示例：

```
skills 示例:
  简历写"MySQL 分库分表"      → 抽 "MySQL" ✅ (不是 "SQL" ❌)
  简历写"Spring Boot 微服务"  → 抽 "Spring Boot" ✅ (不是 "Java" ❌)

work_years 示例:
  经历为 2020.07-2022.08 与 2022.09-至今 两段
  → 总跨度 2020.07 至今 ≈ 4 年 → work_years=4 (不是最近一段的 2 年)
```

## 六、经验沉淀

1. **评测集要"脏"**：全标准集的 100% 是同源偏差，困难集才能暴露真问题
2. **数据链路思维**：解析(技能抽取) → 向量 → 推荐匹配，上游 1% 的改进会放大到下游
3. **Prompt 工程**：文字规则 < few-shot 示例；改完必须复测闭环验证
4. **诚实报告**：95% 的可信数据 + 迭代过程，比 100% 的完美假象更有说服力
