## 一、项目背景与定位

### 1.1 行业痛点

数字经济背景下,新一代信息技术领域(人工智能、大数据、智能系统、物联网等)的岗位体系正在高速演化,但传统岗位分析手段存在三个结构性问题:

1. **数据"时滞"**:岗位能力画像依赖静态字典与人工调研,市场上已经爆发的新技能(如 AIGC 相关技能)迟迟进不了分析体系;
2. **数据"噪音"**:招聘平台的岗位说明书(JD)普遍存在"抄袭"与"技能通胀"现象——同一份 JD 被反复复制、技能要求被无节制堆砌,直接据此构建能力图谱会得到失真结论;
3. **能力"幻觉"**:大模型直接生成的岗位画像看似专业,但可能臆造并不存在的技能要求,缺乏真实数据核验机制。

### 1.2 项目定位

岗能智绘是一套**数据驱动的岗位能力动态演化与分析系统**,以真实招聘数据为底座,打通:

```
多源数据采集 → 新岗位发现与定义 + 既有岗位能力动态更新 → 能力图谱动态演化
            → 简历智能解析 → 精准人岗匹配与差距分析
```

的全流程闭环。系统立足真实爬取的 **10,000 条 AI 算法方向岗位数据**与 **60+ 项技能字典**,让岗位能力画像"从数据中长出来、随数据持续演化",而不是一次性静态产物。

### 1.3 岗位选择范围

紧扣赛题"立足数字经济、瞄准新一代信息技术"的要求,系统当前覆盖人工智能核心方向岗位(机器学习/深度学习/大模型算法、自然语言处理、计算机视觉、数据挖掘、智能制造等),并天然支持横向扩展:更换爬虫数据源(如物联网、大数据开发方向)后,发现、演化、匹配全链路能力即刻复用,无需修改系统代码。

## 二、系统总体架构

### 2.1 三层服务架构

```
┌─────────────────────────────────────────────────────┐
│  前端展示层  Vue 3 + Element Plus + ECharts           │
│  数据大盘 / 知识图谱 / 岗位推荐 / 求职顾问 / 数据管理     │
├─────────────────────────────────────────────────────┤
│  业务后端层  FastAPI(Python 3.11,全异步)              │
│  推荐引擎 / 统计分析 / 新岗位发现 / 新兴技能闭环 / 图谱服务 │
├─────────────────────────────────────────────────────┤
│  大模型引擎层(独立服务,由队友负责,详见其文档)            │
│  简历解析 / 求职顾问                                   │
├─────────────────────────────────────────────────────┤
│  数据存储层  四库协同                                  │
│  MySQL(主库) + Elasticsearch(全文检索)               │
│  + ChromaDB(向量库) + Neo4j(知识图谱)                │
└─────────────────────────────────────────────────────┘
```

### 2.2 四库协同设计

同一份岗位数据同时写入四种存储,各取所长:

| 存储 | 职责 | 支撑的功能 |
|---|---|---|
| **MySQL 8.0** | 业务主库,事务与关联查询 | 岗位/公司/技能字典/简历/推荐流水/收藏投递 |
| **Elasticsearch 8.11** | IK 中文分词全文检索 | 职位搜索、新兴技能转正后的历史 JD 全文回溯 |
| **ChromaDB** | 向量语义检索 | 岗位向量召回("语义相近但技能词不重叠"的岗位) |
| **Neo4j 5.x** | 知识图谱 | 岗位方向全景图谱(技能点粒度) |

主库表结构覆盖系统全链路:业务表(岗位/公司/技能字典/简历/推荐流水/收藏投递等)之外,大模型引擎的 **9 张模块表**(聊天会话/聊天消息/Agent 执行追踪/运行指标/回答质量评价/用户配额/技能分类体系/行业配置/能力关系)也由**主后端统一建表**;引擎侧仅保留懒加载的幂等自建逻辑作为兜底(不使用则不触发),两套定义均为 `IF NOT EXISTS`,表结构一致性有双保险。

四库通过**一键同步管道**保持一致,四个步骤依次执行、独立容错:

1. **MySQL 导入**:读取爬虫 JSON 入库,并基于最新数据**动态重算 Top 15 热门技能**;
2. **ES 同步**:删除旧索引、按预定义 mapping(含 IK 分词)重建,MySQL 全量拍平冗余后 bulk 写入;
3. **ChromaDB 向量构建**:JD 文本经大模型 embedding 向量化;**子进程隔离执行**,防止embedding 长任务阻塞后端事件循环;智能判断全量重建还是增量补充;
4. **Neo4j 图谱重建**:清理旧子图后按最新数据重建岗位方向图谱。

前端每 5 秒轮询各步骤状态(pending/running/done/failed/skipped),四步进度条实时推进。

### 2.3 幂等设计:管道可反复执行

数据管道会被反复触发(每次爬新数据都要重跑、用户可能连点、失败后需要重试),全链路按幂等标准设计:

| 环节 | 幂等手段 |
|---|---|
| MySQL 导入 | 岗位按唯一标识判重,已存在跳过/更新;公司 upsert;技能关联重复写入自动收敛 |
| ES | 删索引重建,重复执行结果一致 |
| Neo4j | 先清旧子图再重建 |
| 建库建表 | `CREATE TABLE IF NOT EXISTS`,bootstrap 可重复调用 |

即"同一个操作执行 1 次和执行 100 次,系统最终状态完全相同",这是数据层可靠性的基础承诺。

### 2.4 技术栈

- **前端**:Vue 3 + Vite + Element Plus + Pinia + ECharts 5 + Vue Router
- **后端**:FastAPI + SQLAlchemy 2.0(全异步)+ MySQL 8 + Redis + JWT 认证
- **大模型接入**:主后端统一封装 LLM 调用(智谱 GLM-4 系列为主),用于推荐精排、新岗位画像、技能别名精判等场景,调用失败自动重试并降级回确定性算法
- **部署**:Docker Compose 一键起 6 个容器(前端 Nginx / 后端 / 大模型引擎 / MySQL / ES / Neo4j),ES 镜像自建集成 IK 分词插件

## 三、核心功能(对照赛题要求)

### 3.1 多源数据采集与一键入库

> 对应赛题"多源数据采集"环节,也是解决数据"时滞"问题的入口——新数据随时爬、随时一键进系统。

- **独立爬虫服务**(由队友负责):从主流招聘平台采集 AI/算法方向岗位,在源头完成字段抽取与初步清洗后落盘为标准 JSON,当前数据量 **10,000 条**;
- **入库前预览**:管理员在数据管理页直接预览爬虫文件的条数与逐字段填充率(标题/薪资/学历/技能等字段完整度一目了然),源头数据质量入库前心中有数;
- **一键同步四库**:管理员点一次按钮,MySQL / ES / 向量库 / 图谱四个存储按 2.2 节管道依次重建,四步进度条实时推进,任一步失败不影响其他库可用性;
- **首次部署免登录初始化(bootstrap)**:新环境部署后无需手工造数据——登录页点"首次部署?初始化系统",后端自动建库建表、灌入技能字典种子数据与演示数据,从部署到可用全自动;
- 全链路幂等(见 2.3),重复导入不产生脏数据。

### 3.2 新岗位发现与定义(核心功能 1)

识别市场上正在萌芽但尚未被标准化的新岗位,并自动生成岗位定义。采用**两步大模型法**,每一步都以真实数据为证据:

**第一步「起名」——从数据异常中发现苗头**

取系统自己算出的"需求飙升技能榜"Top 10 + 近期职位标题抽样,交由大模型归纳出 3~5 个新兴岗位名。Prompt 强制约束:**岗位名必须复用招聘标题中出现过的原词**,从机制上杜绝模型凭空捏造岗位。

**第二步「画像」——用真实 JD 做证据归纳定义**

对每个候选岗位名,先用 ES 检索出真实 JD 摘录作为输入证据,再由大模型归纳四要素,生成完整岗位定义:

- **岗位名称**
- **核心职责**
- **必备技能**
- **加分技能**
- **典型行业应用场景/行业方向**

**工程保障:**

- 每个岗位的画像生成是**独立事务**,单个岗位失败(模型超时、JSON 解析失败)不影响其余岗位;
- 全局状态机维护发现进度(总数/已完成/失败),前端进度条实时轮询,长任务不白屏;
- **支持人工优化与动态更新**:管理员可在线编辑任意岗位定义的名称与四要素;人工修正过的岗位(source=manual)在触发新一轮发现时**不会被自动流程覆盖**,人工意志始终优先。

> 关键设计原则:**LLM 只负责"归纳",证据全部来自真实 JD**——这是幻觉防控的第一道闸。

### 3.3 既有岗位能力动态更新(核心功能 2)

针对已有岗位,识别其能力要求随时间的变化,并提供可干预的更新机制:

- **技能需求演化视图**:数据大盘"技能需求演化"Tab,任选多个技能绘制月度需求量多线折线图,直观呈现某岗位方向的能力要求如何随时间此消彼长(哪个技能在崛起、哪个在衰退),为能力更新提供数据依据;
- **新兴技能转正回溯**(核心更新机制):一个新词(如 "AIGC")被管理员确认转正后,系统自动执行两级回溯:
  1. **职位侧**:全文检索扫描所有历史 JD,正文提到该词的岗位自动补上这条技能关联,并同步更新检索索引(搜索/筛选立即生效)——**既有岗位的能力项实现"新增"**,且每一条例都有 JD 原文可查(数据源可追溯);
  2. **简历侧**:重新扫描历史简历的解析原文,补上该技能——人的能力标签同步更新;
- **岗位定义人工修正**:新岗位定义支持管理员在线编辑,形成"机器发现 → 人工优化 → 动态更新"的持续演化闭环;
- **热门技能动态重算**:每次一键入库后,系统按最新数据重算 Top 热门技能,图谱与统计口径始终贴合企业最新岗位需求,而不是建库时的快照。

### 3.4 新一代信息技术岗位全景图谱(核心功能 3)

- **技能点粒度**:图谱节点细化到"技能点"级别,岗位方向节点与技能、学历、经验、薪资、城市、福利等要素以具名关系连接——`DEMANDS`(核心技能,按方向内岗位覆盖率排序)/ `POPULAR_IN`(岗位集中城市)/ `COMMON_EDUCATION`(常见学历要求)/ `COMMON_EXPERIENCE`(常见经验要求)/ `COMMON_SALARY`(典型薪资段)/ `COMMON_BENEFIT`(常见福利)/ `SIMILAR_TO`(相似方向,按岗位重合度计算),方向画像由结构化三元组而非自然语言描述构成;
- **按技术栈切换视图**:前端方向选择器实时联动 Neo4j,切换"大模型算法 / 自然语言处理 / 计算机视觉 / 智能制造"等方向即重新拉取对应子图,ECharts 力导向布局(force layout)流畅重排;顶部状态栏实时显示当前子图的节点数与关系数;
- **级别视角**:数据大盘的"经验 × 薪资"雷达图提供按经验级别(应届/1-3年/3-5年/5-10年)的维度视图,回答"同一方向不同级别的要求差异";
- **方向画像一句话**:每个方向附带一句自动生成的画像摘要("核心技能包括…；热门就业城市包括…；常见学历要求为…；平均月薪约…"),**由图谱中的结构化关系数据模板化生成,不经过大模型**——每个字都有图数据出处,零幻觉风险,帮助用户快速理解方向定位;
- **降级容错**:Neo4j 不可用时前端自动切换内置演示数据并明确标注"⚠ 演示数据",任何环境下图谱页永不白屏。

### 3.5 人岗匹配度诊断与差距分析(核心功能 4)

#### 3.5.1 简历智能解析(真实简历准确率 96.0%)

- 支持 PDF / Word 上传,由大模型引擎完成"文件→文本→结构化 JSON"解析(引擎内部实现见队友文档);
- 主系统侧负责:文件存储、解析状态机管理(pending → parsing → done/failed,前端实时可见解析进度),以及关键的**技能字典归一化**——解析出的技能名按字典(name + alias)归一后入库,"sklearn" 和 "scikit-learn"、"PyTorch" 和 "pytorch" 在系统里是同一个技能点,保证后续匹配的口径一致;
- 解析失败的简历可重试,失败原因可见。

#### 3.5.2 三段式混合岗位推荐(真实简历 Precision@5 = 90.8%)

```
召回层   ① 技能召回:SQL 统计每个岗位命中简历几个技能,
           必备技能(is_must=1)按 2 分加权, 取 Top 30
        ② 向量召回:简历文本(求职意向+技能+经历)经 embedding-3 向量化查 ChromaDB,
           补上"词面不重叠但语义匹配"的技能召回盲区, 取 Top 30
粗排层   两路召回按 job_id 求并集 → 分数量纲统一到 0~100
        (技能分以命中 5 个技能为满分基数, 防"只要求 1 个技能"的岗位虚高;
         融合分取两路较大值——任一通道强匹配即进入候选) → 排序取 Top 15
精排层   大模型(glm-4-flash)对 Top 15 逐个打分 + 生成一句话推荐理由
        → 截断取 Top 10 落库
```

工程细节(每一条都是踩坑后的沉淀):

- **防资历错配**:向模型显式传入候选人工作年限,并要求其对资历不匹配扣分;
- **硬规则代码兜底**:不完全信任模型输出——资历错配由代码强制乘法降权(社招候选人匹配实习岗打 5 折,应届/在校生匹配资深社招岗打 7.5 折),模型不执行也生效;
- **失败降级**:LLM 超时/失败自动重试 1 次,彻底失败则回退融合分 + 默认理由,**推荐功能在任何情况下都有结果返回**;LLM 漏打分的岗位用融合分补齐;
- **全程可审计**:每次推荐的技能召回分、向量召回分、融合分、LLM 分四路分数快照全部落库(Recommendation 流水),任何一次推荐结果都可回溯复核。

#### 3.5.3 AI 求职顾问(多智能体,由队友负责)

系统内置多智能体求职顾问(1 个 Master Agent + 5 个子 Agent),支持岗位分析、能力差距分析、学习路径规划、趋势预测、综合报告等对话式服务,前端可视化展示思考过程与子 Agent 调用情况。**该模块详细设计与实现由队友负责,见其补充文档。**

### 3.6 新兴技能发现闭环(特色机制)

系统解决"时滞"问题的核心创新,形成完整闭环:

```
发现  简历解析 / 爬虫入库时,字典未命中的技能词不丢弃,
      进入新兴技能候选表(计数 + 首末次出现时间)
        ↓
榜单  双榜呈现:
      · 需求飙升榜——时间切片增速算法(默认近 3 个月需求量 vs 前 3 个月),
        早期样本 <5 条过滤、增速 <2 倍不上榜,防止小样本抖动造假象
      · 新词候选榜——字典外全新词汇,按出现频次(upsert 累计计数)排序
        ↓
转正  管理员在数据大盘勾选确认 → 三段式别名判定:
      规则匹配(标准名/别名精确) → 相似度召回 TopK 候选 → LLM 精判;
      判定为老技能别名(如 "K8s" 之于 "Kubernetes")
        → 归并进该技能的别名表,不新建词条;
      判定为真新词 → 才新建词条进字典
        ↓
回溯  ES 全文扫描历史 JD 补技能关联 + 历史简历补标签(见 3.3),
      别名归并的回溯同样挂在老技能上
        ↓
生效  搜索、推荐、图谱、统计全链路立即识别该技能
```

至此,"市场上刚冒头的技能"从第一次出现在 JD 里,到进入系统分析体系,**不需要改一行代码、不需要等版本发布**。这个机制同时构成了能力图谱动态演化的底层驱动。

### 3.7 数据大盘与求职全流程功能

- **数据大盘**:5 张核心指标卡(岗位总数/公司数/技能数/平均薪资等)+ 12 个统计接口支撑的 7+ 种图表:薪资分布柱状图、城市分布横向渐变柱状图、热门技能榜、行业占比饼图、职位发布趋势折线、技能月度趋势多线图、经验 × 薪资雷达图;
- **新兴技能管理**:候选词列表 + 飙升榜双 Tab,管理员勾选"转正所选"一键完成转正与回溯;
- **求职闭环**:职位收藏、投递记录管理(已投递/约面/offer 状态流转)、个人中心资料维护;
- **职位检索**:ES 驱动的关键词搜索 + 薪资/经验/学历/行业多维筛选,搜索词高亮,详情页展示技能标签与公司信息。

## 四、技术创新点(对照创新性要求)

### 4.1 多源异构数据清洗与交叉验证机制

数据清洗分两侧协作:**源头侧**由爬虫服务在采集时完成字段抽取与初步清洗(由队友负责);**平台侧**由本系统承接,针对 JD"时滞"与"噪音"问题建立三层机制:

1. **LLM 核验式交叉验证**:随机抽取 100 条 JD,用大模型核验"平台标注的技能标签是否被 JD 正文实际支持"——结果 **91.6% 一致(384/419),8.4% 为平台标签噪音**(35 个标签不被正文支持)。这既是质量评测,也是对"JD 抄袭/通胀"现象的**量化实证**,直接论证了多源异构数据必须交叉验证清洗的必要性;
2. **新兴技能机制对抗时滞**:新技能从出现到入库零延迟(见 3.6),画像永远跟着市场走;
3. **字典归一化对抗异构**:同一技能的不同写法(别名、大小写、中英文)统一归一,多源数据在字典层对齐;简历解析、职位导入、新兴技能转正三处入口共用同一套归一规则,其中转正环节采用"规则匹配 → 相似度召回 → LLM 精判"三段式判定——新词若被判定为既有技能的别名(如 "K8s" 之于 "Kubernetes"),自动归并进该技能的别名表而非新建词条,字典不会在演化中膨胀出重复技能;

### 4.2 能力"幻觉"防控体系(六道防线)

| 防线 | 机制 |
|---|---|
| 证据约束 | 新岗位定义必须由真实 JD 摘录归纳生成;岗位名必须复用招聘标题原词,禁止模型凭空发挥 |
| 字典校验 | 所有技能词以字典为准归一化;模型输出的"生造技能"进入候选表接受计数与增速双重检验,达标才允许转正 |
| 别名精判 | 转正时由 LLM 判定新词是否为既有技能的别名,防止字典演化出重复词条;LLM 判定结果**必须落在候选集内**,越界输出一律作废按新词处理 |
| 交叉验证 | LLM 反向核验平台标签,噪音可量化、可定位(8.4%) |
| 人工闭环 | 岗位定义、新兴技能均设人工审核/修正入口,人工修正结果不被自动流程覆盖 |
| 降级兜底 | LLM 失败自动重试 + 降级回确定性算法;硬性规则(资历错配降权)代码强制执行,系统正确性不绑定模型稳定性 |

### 4.3 大模型 + 知识图谱 + RAG 的深度融合

- **知识图谱不只是展示层**:Neo4j 中的岗位-技能-学历-薪资关系为能力分析提供结构化底座,图谱内容随一键同步持续重建,是"动态图谱"而非静态挂图;
- **RAG 双路召回**:向量语义召回与技能精确召回互补,解决"词不匹配但语义匹配"问题,量纲统一后融合,再由 LLM 精排——三层各司其职,任何一层失效都有兜底;
- **大模型承担归纳类工作**:简历解析、推荐精排、新岗位画像、方向画像——每一处输出都被 4.2 的幻觉防控体系约束,模型是工具而非权威。

### 4.4 工程可靠性设计

- 四库同步管道幂等(见 2.3)、分步容错、前端进度可见;
- 向量库构建为分钟级长任务(embedding,即把全部岗位文本逐批发给大模型转成数字向量),采用**子进程隔离**执行,不阻塞主服务——一键同步跑多久,网站都照常可用、进度条照常刷新;
- 图谱服务降级演示数据,演示环境永不白屏;
- 推荐四路分数快照落库,结果可回溯可审计。

## 五、评测结果概览

> 本节仅列核心结论;完整测试方案(测试集设计、用例明细、执行过程、逐题分析)见单独提交的《测试文档》。

### 5.1 三项核心指标(赛题要求 ≥90%)

| 指标 | 结果 | 样本与方法 |
|---|---|---|
| **简历提取准确率** | **96.0%**(技能召回 89.8%) | 13 份真实简历,人工标注答案,逐字段评分 |
| **人岗匹配准确率** | **Precision@5 = 90.8%**,Top1 相关率 100%,MRR = 1.00 | 13 份真实简历 × 人工标注推荐相关性 |

三项指标全部 ≥90%,JD 测试样本 100 条,满足"≥100 条岗位 JD 及测试用例"的可验证性要求。

### 5.2 补充评测

- **合成简历集**:10 份标准简历 + 6 份高难度仿真简历(故意埋入隐含年限、无技能栏、别名、错别字、字段矛盾等陷阱),解析综合字段准确率 **95.8%**;匹配测试 160 个"简历-岗位"对,命中率 **100%**、Top1 相关率 100%;
- **评测驱动迭代**:开发全程采用"评测 → 分析掉分点 → 优化 → 复测"的闭环迭代方式,评测不仅用于验收,也直接反哺了解析策略与系统机制的设计。

## 八、总结

岗能智绘的核心主张是:**岗位能力画像不应该是一次性的静态产物,而应该是一个由真实数据驱动、随市场持续演化、每一步都可验证可干预的活系统。**

- **全流程闭环**:采集 → 发现/更新 → 图谱 → 解析 → 匹配,无一缺失;
- **三项准确率全部 ≥90%**,100 条 JD 测试用例,指标可复现;
- **新兴技能闭环 + LLM 交叉验证**直接回应了数据"时滞"与"噪音"两大痛点;
- **六道幻觉防控防线**保证图谱构建的科学性;
- **Docker 一键部署**,技术方案可迁移至任何新一代信息技术岗位方向——换一个爬虫数据源,整套发现、演化、匹配能力即刻复用。
