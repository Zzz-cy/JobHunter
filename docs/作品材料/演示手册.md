## 二、启动系统（从 Docker 开始）

### 场景 A：本机之前跑过（卷还在）——最常见

```bash
cd C:\GitHub\JobHunter
docker compose up -d
docker compose ps
```

等 1~2 分钟让容器全部就绪。看到 `jh_frontend` / `jh_backend` / `jh_llm` / `jh_mysql` / `jh_es` / `jh_neo4j` 都是 `Up`（backend/llm/es/mysql 带 healthy）就行，**不需要重新初始化**，数据都在卷里。

浏览器打开 `http://localhost`，能看到登录页即成功 → 直接跳第四章。

### 场景 B：全新环境（或卷被清过）

```bash
cd C:\GitHub\JobHunter
docker compose up -d --build   # 首次构建约 5~10 分钟，取决于网络
docker compose ps              # 确认 6 个容器都在运行
```

启动的容器（nginx 只暴露 80 一个对外端口，其余全在内部网络）：

| 容器 | 是什么 |
|---|---|
| `jh_frontend` | 前端 Nginx（80 端口，统一入口，按路径分流到 backend/llm） |
| `jh_backend` | 主后端 FastAPI（业务 + 推荐 + 统计） |
| `jh_llm` | 大模型引擎（简历解析 + 多智能体顾问，独立 FastAPI） |
| `jh_mysql` | MySQL 8（业务主库） |
| `jh_es` | Elasticsearch（自建镜像，内置 IK 中文分词） |
| `jh_neo4j` | Neo4j 5（知识图谱） |
| `jh_adminer` | 附送的数据库网页管理（`http://localhost:8080`，想给老师看表数据时用） |

启动后自检（可选，都返回正常即就绪）：

```bash
curl http://localhost/            # 前端页面(返回 HTML)
docker compose ps                 # backend/mysql/es 显示 healthy
```

> 注意首次启动有依赖链：mysql healthy → backend 建完表 → llm 才启动。`docker compose ps` 里 llm 显示 `Up (healthy)` 之前别急着操作。

全新环境继续第三章初始化。

## 五、组件与功能一览（讲解时的"目录"）

### 5.0 组件层：六个容器各是什么（可配合 `docker compose ps` 现场展示）

| 容器 | 组件 | 一句话职责 |
|---|---|---|
| `jh_frontend` | Nginx 前端 | 系统唯一入口（80 端口）：托管 Vue3 静态页面 + 按路径分流（业务→backend，AI→llm） |
| `jh_backend` | 主后端 FastAPI | 全部业务 API：认证/职位检索/推荐引擎/统计/新兴技能闭环/数据管理 |
| `jh_llm` | 大模型引擎（独立 FastAPI） | 简历解析 + AI 求职顾问（Master+7 子 Agent）+ 6 家大模型容灾路由 |
| `jh_mysql` | MySQL 8 | 业务主库：岗位/公司/技能字典/简历/投递 + 引擎运行时表 |
| `jh_es` | Elasticsearch（自建镜像含 IK 分词） | 职位中文全文检索，支撑搜索页和新兴技能历史回溯 |

| `jh_adminer` | Adminer（辅助） | 数据库网页管理（8080 端口），想看库表数据时打开 |

### 5.2 技术说明要点（老师问架构时用）

**一句话定位**：数据驱动的岗位能力动态演化与分析系统——岗位画像跟着真实数据走，每一步可查证、可干预。

**四层架构**：

```
前端 Vue3 + Element Plus + ECharts（14 个页面）
  ↓ Nginx 统一入口(80)，业务→backend(8000)，AI→llm(8001)
业务后端 FastAPI 全异步（推荐引擎/统计/新兴技能闭环/一键同步）
大模型引擎（独立服务：简历解析 + Master/7子Agent 求职顾问，6 家模型容灾路由）
四库：MySQL(业务主库) + Elasticsearch(IK全文检索) + ChromaDB(向量) + Neo4j(图谱)
```

**三个创新点**（每个一句话）：

1. **新兴技能发现闭环**：字典外技能词进候选榜 → 管理员转正（三段式别名判定防重复词条）→ 自动回溯历史数据 → 全链路即刻生效，不改代码不发版；
2. **LLM 反向交叉验证**：用大模型逐标签核验平台标注是否被 JD 正文支持，把"数据有噪声"从感觉变成 8.1% 的量化结论；
3. **六道幻觉防线**：证据约束、字典校验、别名精判、交叉验证、人工闭环、降级兜底——模型只做归纳，每处输出都有确定性机制拦截。

**四库为什么这么拆**：同一份岗位数据四份存储各取所长——MySQL 管事务关联、ES 管中文全文检索、ChromaDB 管语义召回（"技能词不重叠但语义匹配"的岗位）、Neo4j 管图谱关系。一键同步管道四步幂等，重复执行不产生脏数据。

## 六、Q&A 预案

| 老师可能问 | 答 |
|---|---|
| 数据哪来的？ | 独立爬虫服务（`pa/` 目录，Scrapy+Playwright）从主流招聘平台采集，清洗后落标准 JSON，当前 10000 条。换数据源即可迁移到其他领域 |
| 大模型会不会编造技能？ | 六道防线（见上）。核心原则：模型只做归纳，证据全部来自真实 JD，输出再过字典校验/别名精判/人工入口，失败还有确定性算法兜底 |
| 准确率怎么测的，可信吗？ | 双层评测：合成集（标准答案先于简历存在，可控）+ 真实集（13 份老师提供的真实简历，人工标注）。JD 解析是核验式交叉验证，全自动可复现，脚本在 `evaluation/` |
| 为什么选这些岗位方向？ | 赛题"立足数字经济、瞄准新一代信息技术"。方向由正则规则划分（当前 23 个），加规则即可扩展物联网/智能硬件等方向 |
| 部署复杂吗？ | Docker Compose 六容器一键部署，只需装 Docker Desktop；解压后两步初始化即可运行（本手册第二、三章就是完整过程） |
| LLM 挂了系统瘫吗？ | 不瘫。模型容灾路由（主力智谱，DeepSeek/Kimi/通义备选自动降级）；推荐/AI 顾问失败回退确定性算法；Neo4j 挂了图谱页自动切演示数据，不白屏 |
| 并发能力？ | 后端全异步；AI 顾问支持 1000 并发会话，会话消息全量持久化，重启无损 |
| **技能字典是干嘛的？为啥要预填？**（实测被问住过 ⚠️） | 别讲底层，指着页面讲：**"让系统认词的名单"**——简历和 JD 里同一个技能写法五花八门（sklearn / scikit-learn），字典负责认成同一个，统计推荐才有统一口径。初始 110 项是从真实 JD 归纳的高频词，**类比输入法出厂词库**（没人会问"能自动记新词为啥出厂带词库"）；转正闭环管以后的新词——一个管存量一个管增量。杀手锏论据：评测中扩充字典别名直接把解析准确率拉到 96.0%，字典质量是被评测证明的核心组件 |
| 新兴技能功能演示效果不明显？ | 说"**当前数据时间跨度不足**"，别说"数据量不足"：发现机制吃的是时间增速信号（近 3 月 vs 前 3 月对比），现有数据跨度不够看不出趋势；机制链路（候选榜→增速算法→三段式转正→历史回溯）完整可跑。可当场指新词候选榜："不在字典里的词都攒在这，带出现计数，我确认就转正" |

## 七、应急手册（翻车兜底）

| 症状 | 处置 |
|---|---|
| `docker compose up` 后 80 端口占用 | Windows 上常见 IIS/其他服务占 80：`netstat -ano \| findstr :80` 找 PID 停掉，或改 `docker-compose.yml` 前端端口映射（如 `8081:80`）后 `up -d` |
| 容器反复重启 / 起不来 | `docker compose ps` 看哪个挂 → `docker compose logs backend --tail 50`（或 llm/mysql）看日志 |
| 内存不够（机器 <6GB） | 编辑 `docker-compose.yml` 注释掉整个 neo4j 段落重启——图谱页自动降级演示数据，其余功能不受影响；ES 内存也可调小 `-Xms256m` |
| 职位列表空白 | ES 没数据：管理员 → 数据管理 → 重新一键同步两个数据文件 |
| 简历解析一直 pending/失败 | 十有八九是智谱 Key 余额：看 `docker compose logs llm --tail 50`，确认后换 Key 重启 llm 容器（`docker compose restart llm`）；演示时可改用求职者A 的已有解析结果 |
| AI 顾问没响应 | 同上先看 llm 日志；实在不行跳过该幕，岗位推荐页已能体现 LLM 能力 |
| llm 日志出现 MySQL 断连 `(0,'')` | 老已知问题，代码已修自动重连；若仍偶发，`docker compose restart llm` 即可 |
| 时间不够 | 砍单顺序：第 6 幕(可选幕) → 第 1 幕筛选细节 → 第 2 幕关系筛选演示。**保住：岗位推荐 + AI 顾问 + 指标收尾** |
